# 실전 자동매매 워커 (2026-10-22)

## 현재 구현

### 비정상 종료 복구 검증 (2026-10-23)

설정·실행 세대·주문은 DB가 기준이며 감시 상태는 각 판단 주기에 저장한다.
주기 저장만으로 주문을 보호하지 않는다. 외부 전송 전에 submitting을 커밋하고,
응답 후 accepted/unknown을 커밋한다. 접수 번호가 있는 주문은 재실행 시 체결을
대사한다. submitting이 120초 이상 남으면 unknown으로 바꾸고 신규 주문을 막는다.
unknown은 자동 재전송·자동 해소하지 않으므로 원장 확인이 필요하다.

격리 테스트 DB와 모의 증권사로 자식 워커를 실제 SIGKILL하여 전송 전,
증권사 접수 후 로컬 응답 저장 전, accepted 저장 후의 세 지점을 검증했다.
모두 설정·실행 세대가 보존되고 중복 매수가 없었다. accepted 저장 후에는
재실행 시 filled 대사 및 이후 목표수익 매도까지 확인했다. 운영 서버·실제
주문·알림은 호출하지 않았으며 OS 전원 차단이나 디스크 손상 시험은 아니다.

익절은 `take_profit_enabled`로 사용자별 저장하며 기본값은 true다. 기존 필드가 없는 설정도 true로 처리하여 기존 자동매도를 유지한다. 매도 컬럼의 ‘익절 사용’ 변경은 항목별 자동 저장 API로 즉시 저장하고 실행 세대·active 상태는 유지한다. 워커 신호와 전송 직전 판단 모두 이 플래그를 확인한다. 해제하면 수익률 조건만 비활성화하며 손절은 독립 동작한다. 다시 켜면 다음 판단부터 적용된다. 이미 접수된 주문을 취소하지 않는다. 익절·손절 모두 해제 시 자동 청산 조건이 없음을 확인창에 경고한다.

종목 매매의 첫 번째 종목 컬럼에 상태 배지를 표시한다. 정상 감시·자동 주문 체결 확인 중에는 회전 애니메이션, 신규 주문 차단·예약 대기·정지·오류에는 구분된 정적 표시를 사용한다. 5초마다 사용자별 워커 상태와 최신 안전 옵션을 조회하며, 연결 실패나 오래된 워커 하트비트는 실행 중으로 표시하지 않는다. 감시 중은 매수 완료를 의미하지 않는다. 조회 화면은 주문·시작·정지 상태를 변경하지 않는다.

웹서버 lifespan이 논리 워커를 시작·종료한다. 기본 5초 주기로 DB의 사용자별 활성 자동 설정을 읽는다. 브라우저를 닫거나 로그아웃해도 서버가 켜져 있으면 계속 동작한다. 서버·PC 종료/절전 중에는 동작하지 않는다. PostgreSQL advisory lock(로컬 SQLite는 OS 파일 잠금)으로 같은 DB의 처리 주기를 직렬화한다.

실행 대상은 종목 매매 화면에서 사용자가 **시작/예약 확인창 승인**한 설정뿐이다. 항목별 설정은 입력 완료(change) 즉시 사용자별 DB에 자동 저장하며, 조건 저장 버튼은 사용하지 않는다. 저장·화면 진입·자동 유형 선택만으로 활성화하지 않는다. 시작 승인에는 사용자·테넌트·설정 버전·실행 세대 및 검증된 실전 연결/키 버전을 저장한다. 중지·수동 전환·연결 변경은 신규 실행을 막는다.

자동 저장은 사용자·설정 행 잠금과 버전 검사를 거쳐 한 항목만 병합한다. 실행 중에는 active·auto_control 실행 세대·연결 승인 및 기존 회차를 보존한다. 매수 대기 중에는 변경한 가격·수량을 다음 판단에 사용한다. 보유 중에는 변경한 익절·손절 조건을 다음 판단부터 사용하며, 변경 자체로 추가 매수 회차를 만들지 않는다. 이미 접수한 주문은 변경·취소하지 않는다. 수동 유형 전환만 자동 실행을 정지하며, 자동 유형으로 다시 전환해도 직접 승인 전에는 실행하지 않는다. 수동 주문 수량·지정가격도 저장·복원한다. 저장 성공/실패를 표시하고 모든 변경을 감사 이력에 남긴다. 동시 변경 충돌은 덮어쓰지 않고 재조회를 요구한다.

종목별 최근 상태는 DB에 저장하고 상태/사유 전환은 사용자별 감사 이력에 남긴다. 브로커 오류·호출 제한은 최소 30초 뒤 재시도하며 결과 불명 주문을 다시 전송하는 재시도는 하지 않는다.

이번 버전은 별도 `live_trade_tasks`/현금예약 테이블 대신 기존 `TradePlan.value`의 승인·상태와 `TradeOrder`의 유일 요청키를 사용한다. 기존 설계 계획의 모든 후속 기능이 구현됐다는 의미는 아니다. 사용자·증권사별로 미확정 주문이 하나라도 있으면 추가 주문을 막는 보수적인 입장 제어로 계좌 간 병렬 실행도 제한한다. 끝 4자리 일치만으로 주문을 허용하지 않는다.

## 주문 경계

1. 사용자 활성·역할, 개인 신규주문 차단, 서버 실행 옵션, 실전 연결/승인 버전, 거래일·정규장을 확인한다.
2. 증권사 잔고·매입단가·시세·주문가능 현금/수량을 해당 사용자의 연결로 읽는다. 연속조회가 불완전하거나 값이 불명확하면 주문하지 않는다.

   나무 잔고는 `bnc_bse_cd=1`로 조회하고 `rsdl_qty`(잔량수량)를 현재 보유수량으로 사용한다. 2026-10-23 실제 5주 매수 체결 후 응답은 `itg_bnc_qty=0`, `ny_stl_qty=6`, `rsdl_qty=5`, 매입가격 7,120원이었다. 통합잔고만 사용하면 당일 매수를 0주로 표시하고, 미결제수량을 합산하면 과거 거래를 중복 반영한다. 잔량 필드 누락·음수·소수·비정상 값과 불완전 연속조회는 확인불가로 처리한다. 매도가능수량은 별도 API로 다시 확인한다. 표시·평가손익·자동매매는 동일한 수량 해석을 사용하며 이전 v2 잔고 캐시는 재사용하지 않는다. 필드 정의: [NH PLUG 국내주식 공식 명세](https://www.nhplug.com/openapi-docs/krstock/openapi.json).
3. 공통 `TradingService.preview/execute → TradeGateway.submit/request`를 호출한다. 수동 주문과 다른 우회 전송 함수를 만들지 않는다.
4. **자격증명 준비까지 끝난 후 HTTP 전송 바로 직전**, DB의 신규주문 차단·사용자·설정 버전·활성·세대·연결 승인·미확정 주문을 다시 확인한다. 사용자 DB 게이트를 전송 동안 유지한다. PostgreSQL은 사용자 행 잠금, SQLite는 writer 게이트를 사용한다.
5. 차단 변경과 전송이 동시에 요청되면 이 게이트를 먼저 획득한 작업이 경계를 결정한다. 이미 네트워크 전송 경계를 지난 주문을 체크박스가 소급 취소하지 않는다.
6. `submitting`을 전송 전에 저장한다. 응답 불명은 `unknown`으로 남기고 자동 재전송하지 않는다. 프로세스 종료 후 오래된 전송 중 상태도 불명 상태로 복구한다. 실제 브로커의 exactly-once를 주장하지 않는다.

차단 체크 시 매수·매도 모두 차단한다. 이미 접수된 주문의 체결·취소 확인과 완료 알림은 계속한다. 자동 취소는 하지 않는다. 비활성/조회 전용 사용자는 외부 대사도 실행하지 않는다. 취소 전송은 사용자 최종 확인이 필요하다.

## 조건과 한도

- 가격 매수: 현재가가 기준가격 이하일 때 기준가격을 상한으로 지정가 매수한다.
- 예측 매수: 저장된 당일 유효 예측이 양수일 때 시장가 매수한다. 유료 분석을 자동 실행하지 않는다. 시작 후 1분/예약 시각부터 1분만 신규 진입을 평가하며, 이후 거래일에는 09:00/예약 시각 기준이다.
- 가격 감시는 시작/예약 시각 이후 장중 지속한다. 정지된 설정을 사용자가 명시적으로 새로 시작하고 `매수 사용`이 켜져 있으면, 기존 보유분이 있어도 가격 조건 충족 시 현재 실행 세대에서 한 번 자동매수를 허용한다. 익절·손절 조건은 매수보다 우선한다. 이미 활성인 설정의 재시작·예약·전체 일시정지 후 재개는 보유종목 자동 추가매수를 허용하지 않는다. 일시정지 상태 변경은 저장된 새 시작 자격도 무효화하며, 실행 직전 최신 잔고와 주문 가능 현금·수량을 다시 확인한다. 서버 재시작은 실행 세대나 새 시작 자격을 만들지 않고, 이미 접수된 주문은 취소하지 않는다.
- 목표 매도: 증권사 확인 매입단가 대비 시세 수익률이 목표 이상이면 시장가 매도한다. 수수료·세금·가격 변동으로 실제 실현 수익률은 다를 수 있다. 시작 승인 시 기존 보유분도 감시에 포함함을 명시한다.
- 비중은 주문가능 현금/매도가능 수량에 적용한다. 자동 주문 최대수량은 **기본 1주**다. 매도 비중 계산이 1주 미만이면 최소 1주를 적용하되 매도가능수량·최대수량을 초과하지 않는다.
- 실행 승인 세대·회차·방향별 주문 키를 영속 보존한다. 기본 1회 모드는 매도 체결 확인 후 활성 설정을 끄고 종료 알림을 보낸다. 반복 옵션은 매도 체결과 계좌 잔량 0주 확인 후 다음 회차를 허용하며, 같은 날에도 재매수가 가능하다. 취소·불명 주문 슬롯은 자동 재사용하지 않는다. 중지 후 다시 시작은 별도 명시적 실행 승인이다.
- `accepted`는 체결이 아니다. 확정 체결/취소만 기존 완료 알림을 사용한다. 미확정·결과 불명은 신규 주문을 차단하고 사용자 확인을 요구한다.

키움 `pur_pric` 매입가 필드는 [키움증권 공식 REST 예제](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/examples/%EA%B5%AD%EB%82%B4%EC%A3%BC%EC%8B%9D/%EA%B3%84%EC%A2%8C/get_domestic_account_evaluation_balance.py)를 기준으로 읽는다. 필드가 없으면 임의 원가 추정 없이 자동 매도를 차단한다.

## 운영자가 테스트를 허용하기 전

설치 기본값은 다음과 같다. 이번 구현 과정에서 실제 `.env`의 잠금은 변경하지 않았다.

```dotenv
TRADING_LIVE_WORKER_ENABLED=true
TRADING_LIVE_WORKER_POLL_SECONDS=5
TRADING_LIVE_ORDERS_ENABLED=false
TRADING_AUTOMATIC_ORDERS_ENABLED=false
TRADING_LIVE_ORDER_SCOPE={}
```

사용자가 실전 테스트 허용을 명시한 뒤에만 운영자가 두 실행 스위치를 `true`로 바꾸고, 과거 한정 주문 승인 범위를 검토/정리하고 재시작한다. 이 설정만으로 개인 계획을 활성화하지 않는다. 테스트할 계좌·종목, 비중, 최대수량(권장 초기 1주)을 저장한 뒤 **사용자 본인이** 신규주문 차단 해제와 시작/예약 승인을 한다. 서버 잠금이 남으면 UI에 이유를 표시하고 시작/예약을 비활성화한다.

## 검증/남은 범위

활성 실전 자동매매 사용자의 나무·키움 인증 토큰은 워커 리더가 만료 10분 전부터 사용자별로 갱신한다. 인증 발급만 요청하며 계좌·주문 API를 호출하지 않는다. 나무는 연결·개인 키 버전과 사용자 활성 상태를 재확인한 뒤 암호화 토큰을 적용하며, 키움은 기존 연결 잠금과 60초 재시도 제한을 따른다. 갱신 실패나 만료 시 주문 검증은 계속 차단한다. 갱신 중단·거부는 관리자 설정의 인증 상태를 확인한다.

`tests/test_live_worker.py`: 가짜 브로커로 매수→체결→목표 매도, 차단/정지/수동 전환/권한 변경/버전 변경 직전 경합, 재시작, 0/N개 종목, 사용자·테넌트 격리, 단일 리더, 서버 잠금, 결과 불명 재전송 차단을 검사한다. 외부 실전 주문/알림을 테스트에서 보내지 않는다.

실전 자동 주문의 실제 거래소 체결 및 장시간 운영은 사용자가 소액으로 검증해야 한다. 다중 호스트 장애·DB 연결 상실·브로커 지연의 모든 조합, 독립 outbox의 알림 재시도/배달 보장, 계좌 전체 일일 실현손익, 연속조회 잔고의 모든 페이지 합산은 이번 버전 완료 범위가 아니다. 불완전 잔고는 추정하지 않고 차단한다.
# 자동매매 수명과 알림

활성 설정은 날짜가 바뀌어도 유지된다. 웹서버·워커가 실행 중이어야 하며 정규장·거래일에만 주문한다. 사용자 차단·연결 변경·서버 잠금 등은 매 주문 직전에 재검증한다.

`repeat_trading`은 사용자별 매매 설정에 저장하며 기본값은 false다. 기본 모드는 날짜와 관계없이 1회 매도 체결 후 자동 정지한다. 반복 모드는 정지 전까지 다음 거래일에도 유지된다. 가격 조건은 시작/예약 시각 이후 계속 감시하고, 예측 조건은 당일 유효한 저장 예측과 60초 진입 구간을 요구한다. 따라서 반복 선택만으로 유효 시간 밖의 예측 매수가 허용되지는 않는다. 매도 후 계좌에 잔량이 남으면 다음 회차를 차단한다.

2026-10-23 변경: 다음 시작 승인부터 `entry_policy=buy_then_sell_all`을 저장한다. 기존 보유분이 있어도 현재 회차의 신규 매수 조건을 감시한다. 수량 입력 시 해당 수량을 주문하며 비중으로 줄이지 않는다. 수량 미입력 시 현금 비중을 사용한다. 현금/주문가능수량 부족이면 차단한다. 현재 회차 매수가 체결되면 계좌 평균매입가 기준 목표수익 감시로 전환하고, 목표 도달 시 기존 보유분 포함 전량을 매도한다. 매도에 매수수량 상한이나 비중은 적용하지 않는다. 미확정·부분 체결 주문은 먼저 대사하며, 취소된 무체결 주문은 자동 재전송하거나 기존 보유분을 바로 매도하지 않는다. 활성 실행 중 조건 갱신은 세대/회차 키를 보존하므로 추가 매수 회차가 되지 않는다. 기존 활성 설정은 다음 시작 승인 전까지 종전 정책을 유지한다.

자동 매도 전 최신 증권사 평균매입가를 주문 레코드에 저장한다. 확인된 매도 체결가와 수량으로 `(체결가-평균매입가)×체결수량` 및 원가 대비 수익률을 계산한다. 이 값은 수수료·세금 제외 매매차익이며 과거 평균매입가를 소급 추정하지 않는다. 체결 확인일과 주문일이 달라 일별 귀속이 불명확하면 일일 손익은 미확인으로 남긴다.

시작·예약·정지 및 실행 중 조건 저장에 따른 승인 해제는 사용자 개인 알림 채널로 전송하고 감사 기록에 남긴다. 1회 매매 완료에 따른 자동 종료도 사유와 함께 알린다. 이미 정지된 설정의 반복 정지는 알림하지 않는다. 장 마감은 대기이며 종료 알림하지 않는다. 워커 프로세스 종료는 사용자 설정 정지와 다르다. 알림 전송 실패는 저장된 제어 상태를 되돌리거나 주문을 재전송하지 않는다.
