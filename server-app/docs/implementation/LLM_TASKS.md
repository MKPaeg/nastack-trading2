# LLM 작업별 역할·프롬프트 및 사업 설명 조사

사용자 설정의 `LLM 작업별 역할·프롬프트`에서 각 작업의 목적·실행 시점·사용 모델과 지침을 확인하고 수정한다.

| 작업 | 입력 → 출력 | 실행 |
| --- | --- | --- |
| 사업 설명 인터넷 조사 | 공시·회사 자료 검색 발췌 → 근거 인용이 붙은 사업 설명·주제·불확실성 | 개인 종목 선택 후 조사 버튼 |
| 기본 종목 속성 제안 | 출처 있는 사업 설명 + 등록 차원 → 최대 8개 초기 차원 | 기존 자동 생성 허용 정책 또는 초기화/재시도 |
| 사업 기반 수집 계획 | 저장된 사업설명 + 승인·연결 출처/통계 목록 → 검색어·출처 ID·통계 ID·수집 한계 | 신규 계획 또는 사업설명/지침/모델/출처 정책 변경 |
| 사업 관련 통계 해석 | 실제 관측값·단위·주기 + 사업설명 → 근거 인용·참고 영향/판단 보류 | 통계 내용/사업설명/해석 지침/평가 모델 변경 |
| 뉴스 영향 평가 | 기사 제목·발췌 + 사업 설명 → -4~+4/null, 이유·인용 | 뉴스 평가 실행 |
| 뉴스 번역·요약 | 외국어 제목·발췌 → 한국어 요약 | 번역 버튼 |
| 근거 기반 연구 | 검색 근거 → 요약·동향·위험 | 별도 연구 작업·워커; 서버 연구 기능 허용 필요 |
| 연결 테스트 | 짧은 테스트 지침 → OK 응답 | 연결 테스트 버튼 |

원문·수치 통계를 가져오는 작업 자체, 벡터·주문·실현손익 계산·리포트 조회는 LLM 호출이 아니다. 수집 대상 계획과 통계의 정성 해석은 별도 LLM 작업이다.
프롬프트 편집은 실행 허용·모델/키 변경과 별개다. 편집만으로 유료 호출·재평가·주문을 실행하지 않는다.
입력 비신뢰 처리·도구 및 주문 금지·출력 구조·점수 범위·원문 인용 검증은 수정 불가한 서버 계약으로 마지막에 추가한다.

## 사업 설명

수동 인터넷 재조사·저장 설명·실패 이력 조회는 `데이터 수집 → 사업 설명 재평가`에서 수행한다. 이 화면의 종목 선택은 실행 대상을 고르는 것이며 별도의 모델·프롬프트 설정은 아니다. 저장 설명이 있으면 새 공식 웹 근거와 함께 다시 요약·검증하고, 성공한 결과를 이후 분석에 사용한다. 실패 시 이전 성공 결과를 유지하며 과거 평가·차원은 자동 재계산하지 않는다. 기본 모델과 자동 조사 허용 정책은 사용자 설정에서, 조사 프롬프트는 `LLM 작업별 역할·프롬프트`에서 관리한다.

### 신규 관심·보유종목의 초기 차원 생성 순서

사용자 설정의 `벡터 초기화 전에 사업 설명 자동 웹조사`는 별도 비용·공개정보 외부 전송 동의이며 기본값은 꺼짐이다.
동의한 경우 신규 종목은 Tavily 검색 → 사업 설명 LLM 요약·근거 검증·저장 → 저장 설명을 입력한 초기 차원 LLM 제안 순서로 실행한다.
클라우드 모델은 기존 클라우드 자동 생성 동의도 필요하며, 일회성 승인으로 자동 웹조사를 활성화하지 않는다.
성공한 사업 설명은 재사용한다. 실패·미완료 기록은 자동 재호출하지 않고 사용자가 이력을 확인한 후 명시적으로 조사한다.
조사 결과가 없으면 차원을 확정하지 않고 검토 필요 상태로 남긴다. 수동 속성은 자동 조사와 제안 모두에서 보존한다.
두 단계 프롬프트는 각각 `사업 설명 인터넷 조사`, `기본 종목 속성 제안`에서 편집한다.
LLM이 고르는 것은 탐색용 차원이며 실제 상관계수·벡터 수치나 예측 정확도는 시계열 계산·별도 검증 대상이다.

### 명시적으로 승인한 기존 종목 일회성 재생성

`scripts/reset_owned_profiles.py`는 안정적인 사용자/테넌트 ID, 배치 ID 및 유료 조사·수동 초기화 확인 플래그를 요구한다.
대상은 그 사용자의 활성 관심종목과 저장된 최신 보유종목이며, 매매목록에만 있는 종목은 제외한다.
먼저 사업설명 조사를 완료한 종목만 기존 프로필 전체를 개인 감사 이력 `vector.reset_backup`에 보존하고 초기 차원을 다시 제안한다.
사업설명 실패 시 기존 프로필은 교체하지 않는다. 동일 배치 재실행은 처리·중단 기록이 있는 종목에 외부 호출을 반복하지 않는다.
일회성 재생성은 향후 자동 웹조사·클라우드 호출 동의를 변경하지 않으며 주문·알림을 실행하지 않는다.

조사 버튼은 공개 종목명·코드로 고정 Tavily 검색 API를 호출하고, 공식 DART/KIND 및 검토된 회사 공식 도메인 결과만 사용한다.
기존 공식·사용자 제공 사업 설명 또는 이전 성공한 조사와 새 검색 발췌를 함께 입력해 요약한다. 기존 설명은 증권사 API 본문이 아니다.
기존 자료와 새 자료의 출처·시점을 구분하고, 이전 LLM 요약을 독립 근거로 재인용하지 않고 그 원래 근거를 전달한다.
현재 Trading의 Tavily 연결이 등록되어 있으므로 이를 사용한다. 별도 nastack-agent 설정·다른 비밀정보를 무단 복사하거나 출력하지 않는다.
사용자가 제외한 출처는 검색·결과에서 제외한다. 검색 발췌를 기본 LLM에 전달하고 각 설명의 근거 ID·실제 인용을 검증한다.
임의 URL 직접 방문·본문 전체 크롤링이나 LLM 기억에 의존한 사업 설명 생성은 하지 않는다.
키는 서버에서 선택하며 개인 OpenAI 연결을 끈 경우 공용 키로 대체하지 않는다. Tavily는 명시된 공용 검색 연결을 사용한다.
클라우드 허용과 실행별 검색/모델 비용·공개정보 외부 전송 확인이 필요하다. 구축 검증에서는 실제 유료 호출을 수행하지 않는다.

`business_research`에 소유자·테넌트·종목·요청키와 상태, 근거·모델·프롬프트 당시 본문/버전/hash를 보존한다(migration 0025).
성공한 최신 기록을 개인 종목 속성의 사업 설명으로 읽으며 기존 수동 차원·상관도는 덮어쓰지 않는다.
새 설명은 이후 뉴스 평가와 명시적 기본 속성 재초기화에 사용한다. 과거 평가·설명 이력은 남긴다.
실패·불일치·근거 부족이면 이전 성공 기록을 유지한다. LLM 정리는 검증 완료된 사업 노출과 구분해 표시한다.

## 설정·실행 경계

### 사업 기반 증분 수집·평가 (migration 0026)

종목 상세 재진입과 뉴스 화면의 `사업 기반 증분 수집·평가`는 같은 서버 작업을 사용한다.
흐름은 저장된 최신 사업설명 → LLM 수집 계획 → 승인 출처별 Tavily 검색/고정 통계 원천 → 뉴스·공시 영향 평가 및 별도 통계 해석이다.
수집 계획은 내 기본 분석 모델, 영향 평가·통계 해석은 선택한 뉴스 전용 모델을 사용한다. 각각의 프롬프트는 개인 설정에서 편집한다.

| 단계 | 재사용/갱신 기준 |
| --- | --- |
| 계획 | 사업설명·계획 지침·모델/연결 주소·수집 가능 항목·출처 버전/사용 정책·기간이 같으면 재사용 |
| 뉴스·공시 수집 | 계정 내 공통 원천 수집은 1시간 재사용. KIND 공식 피드를 한 번 수집해 발행사별로 분리하고, EIA/TrendForce의 공통 산업 발견 검색을 공유한다. 국내 기업 뉴스는 종목별 검색. 날짜 경계/기간 확대 시 다시 범위 확인 |
| 통계 원천 | 산업생산 월간 통계는 1일, World Bank 한국 제조업 부가가치·실질 수출 증가율 연간 통계는 7일 내 저장값 재사용. 연간 자료를 월간/거래일 자료로 보간하지 않음 |
| 평가 | 원문 title/excerpt/발행시각 등 증거 내용·사업정보·평가 모델·지침·출처 버전별 재사용. 번역/표시 메타데이터 변경은 재평가 사유가 아님 |

평가는 한 번에 최대 30건, 완료된 평가를 보존하고 남은 미평가만 다음 실행에 이어 처리한다.
별도 화면 새로고침은 조회만 하며, 상세 재진입에서는 서버가 변경/부족 여부를 확인한다. 브라우저의 60초 캐시로 사업설명 변경을 가리지 않는다.
사용자·테넌트·종목별 `collection_workflows`에 계획·완료 단계·검색 범위·진행 토큰을 저장한다. 같은 사용자 작업은 직렬화하고 동일 작업 중복 요청은 실행 중 기록을 반환한다.
실패/처리 여부 불명 작업은 자동 유료 재호출하지 않는다. 5분 이상 미완료이면 확인 후 종료할 수 있고, 실패 단계 재실행은 별도 버튼으로 명시한다.
작업 실행 및 외부 호출 전후에 사용자 활성/역할·소유권·출처/프롬프트/모델·개인 연결을 재검증하며 변경되면 중단한다.

`collection_searches`는 사용자·테넌트·출처 버전·정규화한 실제 질의/요청 옵션·수집기 버전·계획 모델/지침을 키로 영속화한다. 다른 계정의 자료·유료 검색 연결은 공유하지 않는다. 공통 산업 검색은 넓은 발견용 자료 풀이지 모든 종목별 조사 질의를 완전히 수행했다는 뜻이 아니다. 각 회사 사업정보에 대한 영향 점수는 공유하지 않는다. 유료 요청을 보내기 전에 running을 저장하고 처리 불명·실패 요청을 자동 재제출하지 않는다.

계획은 서버가 승인한 연결 목록의 ID만 선택할 수 있다. 공식 피드 연결 출처 외에 승인된 연합뉴스 공개 기사 제목·발췌문의 검색 수집을 지원한다. 일반 웹 검색과 게시일 요청 옵션을 사용하고, 검색 게시일은 최초 발행 또는 수정일의 제공자 추정값임을 기록한다. 피드 원문을 검색 요약으로 덮어쓰지 않는다.
임의 URL 크롤링·유료 뉴스 계약 우회·공시 전문 재무제표 추정은 하지 않는다. 누락 날짜·외부 도메인·미확인 공시는 평가 제외 건수로 표시한다.
현재 구현 통계는 FRED INDPRO와 World Bank 한국 제조업 부가가치·실질 수출 증가율이다. 실행은 개인 출처 정책을 따르며 기존 사용 제외 원천을 임의 활성화하지 않는다. 관련 세부 통계가 없으면 계획의 gaps에 표시하며 임의의 통계나 수치를 생성하지 않는다.
원천 관측값·단위·월간/연간 주기를 보존한다. 통계 해석 점수는 뉴스 합계/주문 판단에 섞지 않고 별도로 표시한다.
게시기간 검색이 해당 기간의 모든 자료를 보장하지는 않는다. 검색 상위 최대 12건, KIND 공식 피드 최대 100건의 제한이 있다. 통계표·대시보드를 뉴스 기사처럼 점수화하지 않고, 제외 사유 및 계정 내 공통 검색 재사용 여부를 상세에 표시한다. 실패한 평가도 실제 NewsRun 링크·완료 수·미평가 수를 보존한다.

연합뉴스의 동일 기사 ID는 모바일 주소·추적 매개변수가 달라도 한 원문으로 취급한다. 과거 원문·평가 이력은 삭제하지 않고 현재 종목별 평가와 합산에서 중복을 제거한다. 다른 출처의 주소나 서로 다른 공시 접수번호를 임의로 합치지 않는다.
운영자용 `refresh_owned_collections.py --reuse-collected-searches`는 저장된 계획이 현재 입력과 같을 때만 기존 검색 기록으로 결과를 정리한다. 검색 시각을 최신으로 위장하지 않으며, 새 검색은 하지 않지만 아직 평가하지 않은 관련 원문은 승인된 LLM 평가를 이어갈 수 있다.
2026-10-24 원천 점검: World Bank 월간 원자재 공식 파일은 HTTP 403, UN Comtrade 공개 API는 최신 요청의 빈 결과 및 HTTP 429로 최신 월간 연결을 완료하지 못했다. 연간 지표와 월간 산업·품목 통계는 별개이며, 접근 불가·관측 누락을 0이나 추정값으로 채우지 않는다.

### 월간 공식 원천 및 실패 평가 복구 보완

- OECD STES `DSD_STES@DF_INDSERV 4.3`, 한국 제조업 `KOR.M.PRVM.IX.C.Y._Z._Z.N`: 2015=100·계절조정 월간 생산량 지수. 공개 SDMX CSV에서 국가·주기·산업·기준연도·단위·조정을 전부 검증한다. 개별 회사나 품목 출하량으로 해석하지 않는다.

- 월간 4종 모두 사용자별 저장·승인 출처 정책·1일 재사용을 적용한다. 원천 표 공개일은 개별 과거 관측값의 최초 공개일이나 point-in-time 빈티지가 아니다. 당월·미래 값은 제외하고 결측·비공개 값은 0으로 만들지 않는다. 조회 실패·단위 변경·승인 철회 시 이전 저장값을 유지한다.
- 2026-10-24 실제 조회: OECD 한국 제조업 80건(2020-01~2026-08), EIA 3품목 각 81건(2020-01~2026-09), 총 323건 저장. OECD 참고용 출처만 요청 범위에서 분석 사용으로 등록했고 기존 IMF/FRED 제외는 유지했다. Comtrade 최신 월간 수출입과 Census 무키 조회는 각각 빈 결과/429 및 키 요구로 미연결이다.
- 기존 `MODEL_INVALID_EVIDENCE_OR_SCORE`는 실패 종류를 구분하지 않아 과거 실패 응답을 복원할 수 없었다. 이제 스키마·원문 외 인용·중복·미평가 누락·불확실 점수·출력 토큰 중단을 구분해 개인 NewsRun에 코드와 원문 ID만 기록한다. 응답 전문·비밀값은 기록하지 않는다.
- 원문에서 추출한 짧은 인용 후보를 제공하되 모델의 실제 인용을 원문과 계속 대조한다. 서버가 잘못된 인용을 다른 문구로 치환하거나 점수를 강제하지 않는다. 한 항목이 잘못돼도 같은 묶음의 다른 원문 중 검증 완료된 평가는 저장하고 다음 명시적 실행에서 재사용한다.
- `scripts/retry_owned_news_run.py`는 사용자가 기존 모델 사용을 명시적으로 선택한 경우만 실행한다. 원래 사용자/테넌트·종목·모델·사업정보·프롬프트·원문 hash·출처 버전을 검증하고, 저장된 원문 및 완료 평가로 미평가만 이어 처리한다. 검색·수집 계획·개인 모델 설정은 변경하지 않으며 새 선택 모델의 평가로 가장하지 않는다. 다른 모델로 기존 점수를 재사용하지 않는다.

프롬프트는 UserSettings의 개인 영역에 작업별로 저장한다. 뉴스는 기존 news_system_prompt 레코드를 그대로 사용한다.
수정은 작업별 버전 검사 + 전체 사용자 설정 버전 CAS/병합을 적용하며 변경 전후 지침은 본인의 감사 이력에 남긴다.
번역은 프롬프트 hash·모델·공급자가 다르면 다음 명시적 번역 때 재생성한다. 연구는 요청 당시 프롬프트 snapshot을 사용한다.
기본 속성의 지침/사업 설명이 변경됐으면 명시적 초기화에서 재제안할 수 있으며 수동 속성은 보호한다.

일반 사용자·관리자는 본인의 설정/조사만 변경한다. 조회 전용은 본인 지침·기록을 읽을 수 있고 변경·조사·연결 테스트는 차단한다.
사업 조사는 실행 전, 검색 후 모델 호출 전, 결과 저장 직전에 사용자 상태·권한·소유 종목·정책·연결을 재확인한다.
요청키는 중복 외부 호출을 막고, 실행 중 기록을 영속화한다. 중단된 작업은 자동 재호출하지 않는다.
5분 이상 미완료인 본인 기록은 확인 후 종료 상태로 정리할 수 있으며 새로운 조사는 다시 명시적으로 요청한다.
